# 1.9.3 日志定位与审批

用户提供 2026-09-23 15:04:12 的 1.9.2 故障报告：OPPO OPD2506、Android 16 / API 36、后台线程、数据读取阶段，NoSuchMethodError 位于 InkStore.annotatedPages:77，经 ReaderNavigationDialog.verifiedInkPages 触发。

## 确认的原因

1.9.2 实际应用 DEX 调用 j$.util.concurrent.ConcurrentHashMap.keySet():ConcurrentHashMap$KeySetView；随包的 classes3.dex 兼容库仅定义零参数 keySet():java.util.Set。返回类型属于虚拟机方法签名的一部分，故此调用不能链接。问题来自包内调用与兼容库签名错配，不能归为 OPPO 缺少 Android API。

同类调用共有三处：annotatedPages 一处，invalidateDocument 的 pending 与 pendingClear 遍历两处。后两处也会参与彻底删除批注的流程，但没有小米的堆栈，不能断言所有删除反馈都只有这一原因。

## 修复与验证方式

- 三个缓存字段使用 ConcurrentMap 静态类型，实际对象仍为 ConcurrentHashMap。keySet 调用使用 Set 返回类型，不改变并发容器与快照语义。
- 导航批注索引读取额外捕获 LinkageError，显示失败提示并保留目录、缩略图和书签。
- tests/desugar-linkage/verify.ps1 解析实际构建 DEX，要求 annotatedPages 一处、invalidateDocument 两处调用均为 keySet():Set，并要求包内兼容库实现该签名。构建在 D8/L8 之后、APK 打包之前执行此检查，失败立即停止交付。
- 旧 1.9.2 构建被该检查按预期拒绝。新版构建与总回归结果以安装包旁验证说明为准。
- InkStoreDeleteTest 新增内存待存笔迹、磁盘 .ink/.bak、无效和越界页码、删除后清空、保留其他文档和清空恢复缓存用例。

本次保留 1.9.2 的压感一致性、局部橡皮、资料库快照与本地诊断。签名继续沿用，版本 1.9.3 / code 14，最低 Android 6 / API 23。尚无 Android 设备安装/触控复测。
