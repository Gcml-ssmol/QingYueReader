## 生产入口验证

新增 tests/note-view-qa/run.ps1，直接编译并执行生产 NoteCanvasView、NoteDocument、NotePageLayout、TouchNavigation、TwoFingerTap、InkStrokeRenderer、InkInput、InkPage、ZoomLimits、NoteActionMenu、NoteActionPlacement。没有复制或重写这些业务算法。

Android View/MotionEvent/Canvas/Dialog 等使用轻量桌面替身。Canvas 记录变换后的绘制命令；它不是 Android 光栅化或完整布局引擎。NoteStore、NoteTextLayout、NoteDialogs 等非目标依赖也作隔离替身，因此不证明磁盘持久化、字体真实排版、图片异步解码或平台 WindowManager 的实际摆放。另以真实 Android API 35 和真实 PDFBox/OCR 依赖编译全部 107 个生产 Java 源文件。

134 条断言覆盖：

- 第 2 页双指缩放保持全局锚点；连续拖动、显式跳 A/B 页、snapshot 恢复和纵横切换重算适配比例。
- 在上下两页同时可见时编辑下方页，笔迹保存为页内坐标；页缝起笔拒绝；跨缝书写钳制在起始页。
- 橡皮与撤销不修改邻页；文本/图片插入、跨页缝拖拽、删除及撤销保持所属页。
- 同屏绘制两页及页偏移；离屏项目不绘制。未覆盖异步图片加载的真实时序。
- 追加/中插页保留缩放与水平锚点；滚动结束结算和恢复页面。
- 笔与手掌混合输入继续写笔迹而不平移或缩放；横向翻页、无限画布平移、dispose 后拒绝输入。
- 菜单五项操作逐一映射，先关闭再回调；页码/导出范围文案；220×180 窄窗口、大字体内容滚动、空 visible frame 回退。

针对已发现的 pinch 缺陷，在 QA 自己的输入快照中仅把 wyGlobal(pinch.oldY) 恢复为旧 wy(pinch.oldY)，测试立即在“pinch on second page stays on second page”失败。随后恢复最终生产输入并重跑通过，证明回归能够捕获实际问题。

独立审查发现并已由原作者修复：pinch 混用页内与全局坐标；菜单最小宽高突破小窗口。父任务发现的显式选页恢复、纵横 baseZoom 与 Window attributes 提交问题也纳入最终版本检查。最终没有新增未解决的阻断缺陷。

跨页选择仍按 1.13.4 NoteDocument.selectPage 的语义清空撤销/重做历史；本轮未扩展跨页历史内存或承诺滚回旧页仍可撤销。验收真机时需检查笔掌接触、长滚动、系统大字体/分屏、真实文本和图片布局、页缝触摸以及窗口坐标。
